# 2.0.4 검증 기록

검증일: 2026-09-08. 배포 소스: `3d137a7ebb3344e38a1795227449a561bad4f121`.

## 변경 범위

실행 코드 변경은 Excel 보고서의 요일 텍스트와 메모 기본 표시 두 곳입니다. SQLite 관련 Rust 코드, 초기 마이그레이션, 앱 식별자 `kr.kar.schedule`, 저장 위치 및 연결 설정 구조는 그대로입니다. 버전은 2.0.4입니다. 회사의 실제 업무 파일과 개인 DB는 수정하거나 배포에 포함하지 않았습니다.

## 완료한 검사

- TypeScript 테스트 29개 통과, 개인 원본 파일을 요구하는 2개는 원본이 없어 건너뜀. Rust 테스트 6개 통과. TypeScript/Vite 빌드와 Mac 앱·DMG 빌드 통과.
- 실제 2.0.3 내보내기 코드로 만든 가상 업무일지를 2.0.4에서 반복 저장. 업무 내용, 여러 줄 한글 메모, 색상, 완료 상태, 행 배치, 병합, 다른 시트 XML 보존 확인.
- 짧은 달, 연말·연초, 윤년 2월 29일의 `일자(요일)` 표시 확인. 상단 1~31 숫자 행 유지.
- 일정 시트가 참조하는 메모 VML에 `visibility:hidden`이 있고 `x:Visible`이 없음을 확인. 메모 문자열을 다시 불러오는 검사 통과. 연결 파일 저장은 다른 내용을 보존하므로 사용하지 않는 이전 VML이 ZIP 내부에 남을 수 있으며, 실제 시트가 참조하는 새 VML을 검사함.
- 별도 Mac QA 프로필에서 2.0.3 앱으로 가상 업무 3개와 기존 연결을 표시한 뒤 종료. 같은 프로필의 앱을 2.0.4로 교체하고 재실행. SQLite 6개 테이블 전체와 스키마 버전이 동일함을 확인.
- 위 2.0.4 Mac 앱에서 실제 ⌘S 실행. 기존 연결 파일 경로에 저장 성공. 저장 후 업무·메모·색상·행 배치·revision이 동일하고 연결 파일 해시만 새 파일에 맞게 변경됨. 저장된 파일의 날짜 표시·기본 숨김 메모·다른 시트 보존 확인.
- [Windows 빌드 34172863087](https://github.com/karkorea-org/kar-schedule/actions/runs/34172863087) 성공. Windows x64 설치 파일과 NAS 실행 ZIP 생성. 로컬 및 읽기 전용 SMB 공유에서 실행·창 생성 확인. 기존 DB와 Excel 연결 정보를 넣은 후 재실행해 모든 테이블 및 원본 파일 해시가 그대로임을 확인. 배포 폴더도 변경되지 않음.
- Mac 앱 버전·식별자 및 ad-hoc 코드 서명 검증. GitHub에 올린 Mac DMG의 SHA-256이 로컬 체크섬과 일치함을 확인.

## 확인하지 못한 범위

이 Mac의 Excel 파일 선택창에서 검증 파일을 선택해도 ‘열기’가 비활성화되어 Excel 본창의 실제 표시 확인은 완료하지 못했습니다. 원인은 확정하지 않았습니다. 파일 내부의 메모 표시 설정과 날짜 값은 검사했으며, 화면 확인용 가상 파일은 로컬 `outputs/Excel-display-2.0.4-review.xlsx`에 있습니다. Windows Excel 화면도 직접 확인하지 않았습니다.

Windows 실행 검사는 GitHub의 Windows 환경과 그 안에서 만든 읽기 전용 SMB 공유에서 수행했습니다. 회사 NAS에서의 전체 직원 업데이트나 실제 사용자 PC의 네트워크 차단 시험은 수행하지 않았습니다. 배포 파일은 기존과 같은 테스트 릴리스이며 Windows 상용 코드 서명 및 Mac Developer ID 공증은 포함하지 않습니다.
